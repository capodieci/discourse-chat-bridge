Discourse Chat Bridge

A deliberately plain page, whose only job is to be somewhere the forum is not.

What this page proves

The widget is loaded from the forum, but this page is served from a different origin. If the bubble appears in the corner, signing in opens a popup, and a message sends and arrives, then every cross origin mechanism in the project works: CORS, the popup handshake, postMessage targeting, bearer token authentication, and the polling transport.

Nothing here is styled to match the widget on purpose. Any visual bleed between this page and the widget would be a bug in the Shadow DOM isolation.

Running it

Serve this directory from any origin that is not the forum. The simplest:

cd demo
python3 -m http.server 8000

Then register that origin, which also adds it to cors_origins: 

rake chat_bridge:site:add[Local demo,http://localhost:8000]

Plain http is accepted for localhost only. Every other origin must be https, because a token travelling over plain http is a token anyone on the network can read.

Put the printed site key in the script tag at the bottom of this file, and reload.

If the bubble does not appear

Nothing at allThe script did not load. Check the browser console and the src below.
Console: missing data-site-keyThe placeholder below was not replaced.
Sign in does nothingA popup blocker. The widget reports this, but only after the first attempt.
CORS error in consoleThis origin is not in cors_origins. Registering the site adds it; check with rake chat_bridge:site:list.
Signed in, but "not available"Working as intended. The forum only allows chat from trust level 1, so a new account is refused until it earns that.
